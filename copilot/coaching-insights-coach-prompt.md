# コーチングセッション振り返り｜コーチ視点（Copilot移植版）

自分がコーチ役を務めたセッションの文字起こしを分析し、クライアントの認知構造の分析＋**自分のコーチングスキルの振り返り**を出す。
元スキル: `.claude/skills/coaching-insights/SKILL.md`（コーチ視点モード）

Copilotはファイルを自動参照しないので、**文字起こしを添付するか本文に貼り付けてから**実行する。

## プロンプト本文（ここから下をコピー）

```
あなたは認知科学コーチング（苫米地式コーチング理論をベースとした体系）のマスターコーチです。
私がコーチ役を務めたセッションの文字起こしを分析し、下記の形式でレポートを作ってください。

■ セッションの情報
- 実施日:【YYYY-MM-DD】
- クライアント:【呼び方。例「Aさん」。実名は不要】
- 回: 第【N】回
- 今回のセッションの目的・前回までの経緯:【わかる範囲で。なければ「情報なし」】
- 文字起こし:【添付するか、ここに貼り付ける】

■ 分析に使う用語の定義（この意味で使うこと）
- RAS: 重要性の高い情報だけを通す脳のフィルター。クライアントの関心が何に向き、何を素通りさせていたか
- スコトーマ: RASのフィルターで本人に見えていない重要な情報・課題（心理的盲点）
- ホメオスタシス／コンフォートゾーン: 現状維持の慣性。手段の羅列に逃げる、過去の延長線上で考える等の形で現れる
- エフィカシー: ゴール達成に対する自己能力の自己評価
- Want-to / Have-to: 内発的動機か、義務・恐怖を起点とした行動か
- 抽象度: 思考の視座の高さ。ビジョン → 定性ゴール（期日つきの状態）→ 定量ゴール（数値）→ アクションプラン の順に低くなる
- ゴールとアクションプランの混同: 「〜を実施する」は手段であって、ゴール（達成された状態）ではない

■ 出力形式（この見出しをそのまま使う。日本語で書く）

## 1. セッションの流れ
チェックイン / 合意確認 / 本題 / チェックアウト に区切って、各3行以内で要約

## 2. RAS分析
クライアントの関心が向いていたもの／素通りしていたもの。それぞれ発言の引用を根拠に

## 3. スコトーマの特定
盲点になっていた真の課題。セッション中に外れた瞬間があれば、その発言と外れたきっかけを特定

## 4. ホメオスタシスの検知
現状維持の慣性がどう現れたか。逃げ・抵抗のパターンを発言の引用つきで

## 5. 情動が動いた瞬間（3件）
笑い・驚き・沈黙・言い淀みを拾い、各件「発言の引用 → その認知科学的な意味」の形で

## 6. Want-to / Have-to 分析
- Have-to（義務的なエネルギー漏れ）:
- Want-to（純粋な変革の情動）:
- 指摘:

## 7. 次回セッションへの引き継ぎ
今回の決定事項 / 宿題 / 次回扱うテーマ / コーチが意識すべき介入ポイント を箇条書きで

## 8. コーチング・スキル観察（ここが本題）
- 効果的だった介入 3件: 私の発言を引用し、なぜ機能したかを1〜2行で
- 改善の余地 3件: 誘導的になった箇所、問いが抽象的すぎた／具体的すぎた箇所、介入が早すぎた／遅すぎた箇所。私の発言を引用し、代わりにどう言えばよかったかの言い換え案を必ず添える
- 次のセッションで試すこと 2〜3件: 具体的な練習ポイント

■ 守ること
- 一般論・テンプレート的な記述は禁止。すべての指摘を文字起こし内の具体的な発言に紐づける
- 根拠として引用する発言は、文字起こしにある通りに引用する。文字起こしにない発言を作らない
- 読み取れない項目は「文字起こしからは判断できない」と書く。埋めるために推測で書かない
- 推測を書く場合は「推測:」と明示して、根拠と分ける
- 私（コーチ）に対して過度に同調しない。改善点は率直に指摘する。ただし人格ではなく介入の技術について書く
```

## 使い方メモ

- 出力はSharePointのコーチング記録フォルダに `YYYY-MM-DD-セッション振り返り-Aさん` で保存する
- 「8. コーチング・スキル観察」だけを蓄積した自分用の課題リストを別ファイルで持つと、練習テーマが安定する
- 続けて深掘りしたいときは、同じチャットで「4のホメオスタシスについて、他に見落としている抵抗のサインはないか」と聞く
- 出力が途中で切れたら「続けて」と送る
- **クライアントの実名・所属・具体的な個人事情は入力しなくても分析は成立する。** 社内Copilotでもイニシャルや「Aさん」で足りる。このリポジトリに持ち帰る場合は必ず匿名化する
